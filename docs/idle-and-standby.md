# Idle activity and standby

In Animation Grid, **May be used while idle** opts an animation into autonomous activity. Save with Save animation. Saved eligibility and mappings determine the idle pool. A pose needs a reachable saved scene placement as well as idle permission; open-floor permission alone does not create a locationless idle candidate. Animations reserved by application mappings are excluded from normal idle candidates. If no eligible saved placement is reachable, the character waits safely and records idle_unavailable. Transition-only sequences never enter the idle pool.

Sitting and sleeping require valid `entry_transition` and `exit_transition` role bindings. Character-owned play-once entry/exit sequences provide these, including later reclining variants. The runtime holds position during transitions, finishes getting up before moving, and finishes an entry before responding to an interruption with an exit. Missing transition bindings prevent entering a resting pose.

Switch 1 enters standby. It cycles through reachable saved standby-eligible rest placements across enabled scenes, with matching transitions. The companion walks there, plays the entry, pauses for 0.75 seconds, then powers down the backlight. Touch, a switch or a key restores the screen before the getting-up sequence. Telemetry still updates while standby suppresses new actions. If no valid rest location with transitions exists, standby powers down after stationary idle instead.

The Pi's `/sys/class/backlight/panel_backlight@1/bl_power` is set to 4 and brightness to zero. Setting `bl_power` alone left this driver's actual brightness nonzero, so both controls are required. Brightness is saved in `~/.deskpal_display_brightness.json` and restored on wake or application restart. Touch and GPIO remain active; the compositor layout is preserved. The app uses the Pi's existing noninteractive sudo access only when a sysfs write requires it. Hardware verification checks actual brightness reaches zero and restores the previous setting in a finally block.

Automatic lux/radar sleep follows the shared bedtime, presence-distance limit and manual wake grace described in [Hardware diagnostics](hardware-testing.md). Bedtime overrides radar wake/keep-awake until sunrise; darkness still uses the configured lux threshold. Ordinary idle rest is not itself display standby. Sleep does not stop producer polling or promise to replay every old event: standby queue compaction/expiry keeps routine work from accumulating indefinitely.

Generated frames and exact prompts: assets/characters/adventurer/transitions_v1/README.md. Existing rest and standing frames serve as endpoints. Original generated pixels remain intact; geometry is controlled through per-frame metadata. The grid and reference sheets use a consistent scale across frames of differing aspect ratios.
